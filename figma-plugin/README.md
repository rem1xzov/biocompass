# Плагин Figma: функциональная архитектура «Биокомпаса»

Плагин для FigJam, который рисует функциональную архитектуру продукта на доске.
Подход взят из цикла Павла Шерера «Функциональная архитектура цифровых продуктов»
([часть 1](https://sherer.pro/blog/funkcionalnaja-arhitektura-cifrovyh-produktov-chast-1/),
[часть 2](https://sherer.pro/blog/funkcionalnaja-arhitektura-cifrovyh-produktov-chast-2/)):
функция — это любое событие системы, функции складываются в разделы, разделы вкладываются
друг в друга, общие функции выносятся отдельно, у функций есть типы и зависимости.

Содержание адаптировано под бизнес «Биокомпаса»: открытая платформа о протезировании,
пользователь сам выбирает организацию, справочник не зависит от рекламы, медицинская
срочность публикуется только после клинической редактуры.

## Шесть фреймов

| Фрейм | Что показывает |
|---|---|
| 1. Функциональная модель | 4 уровня (продукт → разделы → функции → детали), 10 разделов и 83 функции с типами: пользовательская, системная, проверка условия, негативная, позитивная |
| 2. Общие функции и блокировки | 12 переиспользуемых функций (поиск, фильтры, цитата-источник, состояния «неизвестно/пробел») и 7 правил, которые блокируют выполнение |
| 3. Функциональный сценарий | «Нужен центр для ребёнка, рука, по сертификату»: 14 шагов, 3 проверки условия, 2 негативные ветки, успешное завершение |
| 4. Матрица «раздел × компонент» | где живёт функциональность: клиент, API, БД, редакция, партнёрский контур |
| 5. Слой данных | 12 сущностей (статья, утверждение, источник, норма, изделие, организация, точка, кандидат, публикация, пользователь, партнёр, событие) и связи между ними |
| 6. Цикл статей | 12 типовых входов из `routes.json`; опубликованные статьи залиты, материалы в проверке — пунктиром |

## Установка и запуск

1. Сгенерировать файл плагина и проверить сцену:

   ```powershell
   node scripts/build-plugin-data.mjs     # данные + архитектура → figma-plugin/code.js
   node scripts/test-plugin.mjs           # проверка с мок-API Figma + preview/*.svg
   node scripts/render-plugin-preview.mjs # PNG-превью фреймов (нужен Chrome)
   ```

2. Figma Desktop → **Plugins → Development → Import plugin from manifest…** →
   `figma-plugin/manifest.json`.
3. Открыть доску FigJam → **Plugins → Development → Биокомпас · функциональная архитектура**.
4. Плагин добавит шесть фреймов и подгонит вид.

`editorType` — `figjam`, сетевого доступа нет (`allowedDomains: ["none"]`), данные вшиты
в `code.js`.

## Файлы

| Файл | Назначение |
|---|---|
| `manifest.json` | манифест плагина (FigJam, api 1.0.0, без сети) |
| `architecture.js` | **содержание** архитектуры: разделы, функции, общие функции, блокировки, сценарий, матрица, сущности |
| `plugin-body.js` | отрисовка: раскладка, карточки, коннекторы, легенда |
| `code.js` | сгенерированный файл плагина (`KB_DATA` + `ARCH` + отрисовка) |
| `../scripts/build-plugin-data.mjs` | сборка `code.js` |
| `../scripts/test-plugin.mjs` | прогон с мок-API + SVG-сцена |
| `../scripts/render-plugin-preview.mjs` | PNG-превью каждого фрейма |

## Проверка без Figma

`node scripts/test-plugin.mjs` запускает `code.js` в песочнице с мок-объектом `figma`
(фреймы, shape-with-text, text, connector) и проверяет:

- ровно 6 фреймов, обязательные заголовки, ≥80 карточек, ≥40 связей;
- все коннекторы ссылаются на существующие узлы;
- нет пересечений карточек (контейнеры разделов не считаются);
- пишет `reports/figma-plugin-scene.json` и `preview/figma-plugin-architecture.svg`.

Ограничение: это проверка раскладки и данных, а не рендер Figma. Шрифты, автораскладка
текста и вид коннекторов в Figma могут отличаться — после импорта доску стоит один раз
посмотреть глазами.

## Что дальше можно добавить

- Детальные функции (L3) для двух-трёх разделов — по образцу «валидация формы» из статьи.
- Матрицу зависимостей «функция × функция» (кто кого блокирует) вместо списка блокировок.
- Функциональные требования к MVP: только те функции, что нужны на первом релизе.
