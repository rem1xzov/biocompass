# Плагин Figma: функциональная архитектура «Биокомпаса»

Плагин для FigJam, который строит две доски из данных базы знаний:

1. **«Функциональная архитектура»** — входы → разделы приложения → цикл статей по этапам →
   каталог по категориям → слой доказательств (утверждения → источники → политика публикации)
   и правовой контур (нормы, оплата, клиническая редактура).
2. **«Цикл статей»** — 12 типовых входов из `articles/routes.json`: каждая цепочка шагов,
   опубликованные статьи залиты, материалы в проверке — пунктиром.

Это ответ на задачу «взять figma плагин, взять цикл статей, построить функциональную
архитектуру приложения»: архитектура не нарисована руками, а собирается из тех же данных,
что видит продукт, и пересобирается одной командой.

## Установка

1. Сгенерировать файл плагина (он же коммитится в репозиторий):

   ```powershell
   node scripts/build-plugin-data.mjs     # → figma-plugin/code.js (данные + логика)
   node scripts/test-plugin.mjs           # проверка без Figma + preview/figma-plugin-architecture.svg
   ```

2. В Figma Desktop (не в браузере): **Plugins → Development → Import plugin from manifest…**
   → выбрать `figma-plugin/manifest.json`.
3. Открыть доску (FigJam) → **Plugins → Development → Биокомпас · функциональная архитектура**.
4. Плагин добавит два фрейма на текущую страницу и подгонит вид (`scrollAndZoomIntoView`).

`editorType` — `figjam`, сетевого доступа нет (`allowedDomains: ["none"]`), данные вшиты
в `code.js`, поэтому плагин работает офлайн.

## Что внутри

| Файл | Назначение |
|---|---|
| `manifest.json` | манифест плагина (FigJam, api 1.0.0, без сети) |
| `plugin-body.js` | логика: раскладка, карточки, коннекторы, легенда |
| `code.js` | сгенерированный файл плагина: `KB_DATA` + `plugin-body.js` |
| `../scripts/build-plugin-data.mjs` | сборка данных из `kb/kb.json`, `routes.json`, frontmatter статей |
| `../scripts/test-plugin.mjs` | прогон плагина с мок-API Figma + рендер SVG |

## Данные

`KB_DATA` собирается из публикационной выгрузки, поэтому архитектура честно показывает,
что уже можно выпускать:

- `20` статей из `51` опубликовано (остальные — «в проверке», на схеме пунктир);
- `8` этапов из `10` с опубликованным материалом;
- `9` категорий каталога (68 изделий с доказательствами по параметрам);
- `191` утверждение и `94` источника — слой доказательств;
- `12` типовых входов с цепочками шагов.

## Проверка без Figma

`node scripts/test-plugin.mjs` запускает `code.js` в песочнице с мок-объектом `figma`
(фреймы, shape-with-text, text, connector), затем:

- печатает число фреймов, карточек, текстов и связей;
- проверяет инварианты: 2 фрейма, ≥30 карточек, ≥20 связей, обязательные заголовки,
  отсутствие связей в несуществующие узлы, отсутствие пересечений карточек;
- пишет отчёт `reports/figma-plugin-scene.json`;
- рендерит `preview/figma-plugin-architecture.svg` — превью той же сцены.

Ограничение: это проверка раскладки и данных, а не рендер Figma. Шрифты, автораскладка текста
и вид коннекторов в Figma могут отличаться — итоговую доску нужно один раз проверить глазами
после импорта плагина.

## Подпись к задаче

- «взять figma плагин» → плагин для FigJam, импортируется из манифеста;
- «взять цикл статей» → `KB_DATA.stages` (10 этапов × статьи) и `KB_DATA.routes` (цепочки шагов);
- «построить функциональную архитектуру приложения» → фреймы «архитектура» и «цикл статей»
  с разделами, потоками и слоем доказательств.
